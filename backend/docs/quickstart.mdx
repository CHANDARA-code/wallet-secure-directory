<Steps>
  <Step title="Install">
    ```bash
    cd backend
    npm install
    ```
  </Step>
  <Step title="Configure">
    ```bash
    cp .env.example .env
    openssl rand -base64 48
    ```
    Put the generated value in `BETTER_AUTH_SECRET`. It must be at least 32 characters. `TRUST_PROXY_HOPS` specifies the number of reverse proxy hops (0 for direct exposure/no proxy, 1 behind a single reverse proxy like Nginx or AWS ALB). In production (`NODE_ENV=production`), `TRUST_PROXY_HOPS` must be set explicitly. If set to 0 behind a reverse proxy, rate limiting treats the proxy's IP as the client IP, grouping all users into a single rate-limit bucket where one user's failed attempts can lock out all users globally. In non-production environments, it defaults to 0.
  </Step>
  <Step title="Migrate">
    ```bash
    set -a && . ./.env && set +a
    npm run db:migrate
    ```
  </Step>
  <Step title="Run">
    ```bash
    npm run build
    node --env-file=.env dist/main.js
    ```
  </Step>
  <Step title="Check">
    ```bash
    curl http://localhost:3000/api/health
    ```
    The response reports `"journalMode": "wal"`.
  </Step>
</Steps>

## Wallet pass configuration

The backend supports generating native digital wallet passes for Apple Wallet (.pkpass) and Google Wallet (save-to-wallet JWT).

### Signed vs Stub Mode

- **Stub Mode (Default)**: If credentials are not configured, endpoints generate unsigned stubs (`X-Pass-Stub: true` for Apple pkpass; `stub: true` with `alg: "none"` for Google Wallet).
- **Signed Mode**: Activates when all required credentials for the respective provider are configured.

### Apple Wallet Configuration

To produce signed `.pkpass` bundles with detached PKCS#7 signatures, set all required variables:
- `APPLE_PASS_TYPE_ID`: Pass type identifier (e.g. `pass.com.example.wallet`).
- `APPLE_TEAM_ID`: Apple Developer Team ID.
- `APPLE_PASS_CERT_PATH`: Path to PEM certificate file.
- `APPLE_PASS_KEY_PATH`: Path to PEM private key file.
- `APPLE_WWDR_CERT_PATH`: Path to Apple WWDR intermediate certificate PEM file.
- `APPLE_PASS_KEY_PASSPHRASE` (Optional): Passphrase if the private key is encrypted.
- `APPLE_PASS_ORGANIZATION` (Optional): Organization display name (default: `Secure Identity Wallet`).

### Google Wallet Configuration

To produce RS256-signed Google Wallet save JWTs, set all required variables:
- `GOOGLE_WALLET_ISSUER_ID`: Google Wallet issuer account ID.
- `GOOGLE_WALLET_SERVICE_ACCOUNT_EMAIL`: Google service account email.
- `GOOGLE_WALLET_PRIVATE_KEY_PATH`: Path to RSA private key PEM file.
- `GOOGLE_WALLET_CLASS_SUFFIX` (Optional): Pass class suffix (default: `identity_wallet`).
- `GOOGLE_WALLET_ORIGINS` (Optional): Comma-separated list of allowed web origins.

### All-or-Nothing Group Validation

Each credential group is validated independently as all-or-nothing:
- If no variables in a group are set, that provider runs in stub mode.
- If some but not all required variables in a group are set, the application refuses to boot and logs the missing variables.
- All specified certificate and key paths must exist and be readable.

## Using the playground

The interactive API playground sends requests straight from the browser to `http://localhost:3000` (so CORS applies). To use the playground:

- The backend must be running at `http://localhost:3000`.
- `TRUSTED_ORIGINS` in your backend environment must include the docs origin (for example, `http://localhost:3333`).
- Protected endpoints need `Authorization: Bearer <token>` from the `set-auth-token` response header of sign-in.

## Changing the schema

Edit `src/database/schema.ts`, then run `npm run db:generate` followed by `npm run db:migrate`.
